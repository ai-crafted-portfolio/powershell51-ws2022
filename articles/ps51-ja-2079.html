## 記述 **New-NetQosPolicy** cmdlet は新しいネットワーク品質のサービス (QoS) ポリシーを作成します.QoS ポリシーには2つの主要部分があります.フィルターとアクションとして知られるマッチ条件など.Windows Server 2012以降のアプリケーションの名前や TCP ポート番号などのマッチ条件が,そのポリシーに関連するトラフィックを決定します. *DSCPAction*と *ThrottleRateAction*のようなパラメータは,マッチトラフィックをどのように処理するか決定します.マッチ条件とアクションに加えて,ユーザーがQS ポリシーにカスタマイズできる *NetworkProfile*と *Precedence*などの一般的なパラメータもあります.

参数形式で知られているマッチ条件,またはフィルターのリストは以下の通りです: *FCoE*, *Cluster* (3343), *LiveMigration* (6600), *iSCSI* (3260), *NFS* (2049),および *SMB* (445).それぞれ括弧で指定された有名なTCPポートに一致します.唯一の例外は,EtherType 0x8906に一致する *FCoE*です.これらのフィルターはフィルタリング目的で単独で使用する必要があります. 言い換えれば,他のマッチ条件パラメータと混ぜることはできません.

QoSポリシーは複数の場所に保存できます.ユーザーは, *PolicyStore*  параметрを指定することで,場所を選択できます. *PolicyStore*  параметрが指定されていない場合は,新しいポリシーがローカルコンピュータ (localhost) に追加されます.もしポリシーが ActiveStore に保存されている場合,再起動後,ポリシーは持続しません.

## 例えは

### 例1: QoSポリシーを作成します.```
PS C:\> New-NetQosPolicy -Name "SMB Policy" -SMB -PriorityValue8021Action 3
Name           : SMB Policy 
Owner          : Group Policy (Machine) 
NetworkProfile : All 
Precedence     : 127 
Template       : SMB 
PriorityValue  : 3

このコマンドはSMBポリシーという QoSポリシーを作成し,SMBトラフィックを分類し,802.1p優先値3でタグ付けします. SMBパラメータは,SMB向けに予約されているTCPポート445に一致する,内蔵フィルターです.

例2:アプリケーションに一致するQoSポリシーを作成します.```

PS C:> New-NetQosPolicy -Name "FTP" -AppPathNameMatchCondition "ftp.exe" -ThrottleRateActionBitsPerSecond 1MB -PolicyStore ActiveStore Name : FTP Owner : PowerShell / WMI NetworkProfile : All Precedence : 127 AppPathName : ftp.exe ThrottleRate : 1.049 MBits/sec


このコマンドは, ftp.exe のアプリケーションパスと一致する, ftp.exe という QoS ポリシーを作成し,秒速8,000,000 ビットでトラフィックを抑制します.このポリシーは ActiveStore です.つまり,コンピュータを再起動した後は持続できません.

# New-NetQosPolitics について

### 例3:サブネットへのトラフィックをマッチするQoSポリシーを作成します.```
PS C:\> New-NetQosPolicy -Name "Backup" -IPDstPrefixMatchCondition "10.1.1.176/28" -NetworkProfile Domain -DSCPAction 40
Name           : Backup 
Owner          : Group Policy (Machine) 
NetworkProfile : Domain 
Precedence     : 127 
IPProtocol     : Both 
IPDstPrefix    : 10.1.1.176/28 
DSCPValue      : 40

このコマンドは,バックアップという QoSポリシーを作成し,10.1.1.176/28サブネットに送られたトラフィックと一致し,DSCP値40でタグ付けします.このポリシーはドメインに接続されたネットワークアダプターに送られたトラフィックのみで有効です.

例4: ポートに送られたトラフィックに一致するQoSポリシーを作成します.```

PS C:> New-NetQosPolicy -Name "HTTP" -IPPort 80 -IPProtocol TCP -ThrottleRateActionBitsPerSecond 10MB Name : HTTP Owner : Group Policy (Machine) NetworkProfile : All Precedence : 127 IPProtocol : TCP IPPort : 80 ThrottleRate : 10.486 MBits/sec


このコマンドは,ポート80に送信されたTCPトラフィックに一致するQoSポリシーを作成し,秒あたり80,000,000ビットに制限する速度です.

### 例5: 標準 QoS ポリシーを作成する```
PS C:\> New-NetQosPolicy -Name "Wildcard" -Default -MinBandwidthWeightAction 30
Name               : wildcard 
Owner              : Group Policy (Machine) 
NetworkProfile     : All 
Precedence         : 127 
Template           : Default 
MinBandwidthWeight : 30

このコマンドは,ワイルドカードというQoSポリシーを作成し,特定のQoSポリシーに一致しないすべてのトラフィックを捕捉し,そのようなトラフィックに最低帯域幅重量30を割り当てます.

例 6:アプリケーションからの返信トラフィックに一致するQoSポリシーを作成します.```

PS C:> New-NetQosPolicy -Name "IIS" -URIMatchCondition "http://training" -ThrottleRateActionBitsPerSecond 500KB Name : IIS Owner : Group Policy (Machine) NetworkProfile : Domain Precedence : 127 URI : http://training/ URIRecursive : False ThrottleRate : 516.096 KBits/sec


このコマンドは,IISと呼ばれる QoSポリシーを作成し,HTTPサーバアプリケーションからの返信トラフィックと指定された URIを一致させ,回帰トラフィックを秒あたり4,000,000ビットに制限します.

## DESCRIPTION
The **New-NetQosPolicy** cmdlet creates a new network Quality of Service (QoS) policy.
A QoS policy consists of two main parts: match conditions also known as filters, and actions.
Match conditions such as the name by which an application is run in Windows Server® 2012 and later or a TCP port number decide to what traffic the policy is relating.
Parameters such as *DSCPAction* and *ThrottleRateAction* determine how the policy is to handle the matched traffic.
Besides match conditions and actions, there are also some general parameters such as *NetworkProfile* and *Precedence* that the users can customize for a QoS policy.

A list of well-known match conditions, or filters, in the form of parameters is provided: *FCoE*, *Cluster* (3343), *LiveMigration* (6600), *iSCSI* (3260), *NFS* (2049), and *SMB* (445).
Each of them matches a well-known TCP port specified in the brackets.
The only exception is *FCoE*, which matches EtherType 0x8906.
These filters must be used alone for filtering purpose.
In other words, they cannot be mixed with other match condition parameters.

QoS policies can be stored in multiple locations.
Users can choose a location by specifying the *PolicyStore* parameter.
If the *PolicyStore* parameter is not specified, then the new policy is added to local computer (localhost).
If a policy is stored in ActiveStore, then the policy will not persist after reboot.

## EXAMPLES

### Example 1: Create a QoS policy
```
PS C:\> New-NetQosPolicy -Name "SMB Policy" -SMB -PriorityValue8021Action 3
Name           : SMB Policy 
Owner          : Group Policy (Machine) 
NetworkProfile : All 
Precedence     : 127 
Template       : SMB 
PriorityValue  : 3
```

This command creates a QoS policy named SMB Policy that classifies SMB traffic and tags it with 802.1p priority value of 3.
The *SMB* parameter is a built-in filter that matches TCP port 445, which is reserved for SMB.

### Example 2: Create a QoS policy that matches an application
```
PS C:\> New-NetQosPolicy -Name "FTP" -AppPathNameMatchCondition "ftp.exe" -ThrottleRateActionBitsPerSecond 1MB -PolicyStore ActiveStore
Name           : FTP 
Owner          : PowerShell / WMI 
NetworkProfile : All 
Precedence     : 127 
AppPathName    : ftp.exe 
ThrottleRate   : 1.049 MBits/sec
```

This command creates a QoS policy named FTP that matches an application path at ftp.exe and throttles the traffic at 8,000,000 bits per second.
This policy is ActiveStore.
This means that it is not persistent after restart of the computer.
