記述は,

Add-CauClusterRolecmdlet は,指定されたクラスタに自更新機能を提供するクラスタ情報更新 (CAU) クラスタロールを追加します.クラスタにCAUクラスタロールが追加されたとき,クラスタ更新プロセスを調整するために外部コンピュータを必要とせずに,ユーザが指定したスケジュールでクラスタ失敗クラスタが自己更新することができます.

このcmdletを実行するには,各ノードでWindows PowerShell® リモッティングが有効にする必要があります.Enable-PSRemotingcmdlet.さらに,各ノードでWindows リモート管理 - 互換性モード (HTTP-In) ファイアウォール例外が有効であることを確認してください.

例えは

例1: 特定の間隔で指定されたクラスターにCAUクラスタロールを追加する

$parameters = @{
    ClusterName = 'CONTOSO-FC1'
    DaysOfWeek = 'Tuesday',
                    'Saturday'
    WeeksOfMonth = '2',
                    '4'
    MaxFailedNodes = '2'
    MaxRetriesPerNode = '2'
    PostUpdateScript = '\\CONTOSOFileShare\scripts\verifyupdatesinstalled.ps1'
    RequireAllNodesOnline = $true
    EnableFirewallRules = $true
    Force = $true
}
Add-CauClusterRole @parameters

このコマンドは,CAUのクラスタロールを CONTOSO-FC1というクラスタにデフォルト名で追加します.CAUのクラスタロールは,毎月の第2週と第4週の火曜日と土曜日に更新実行するように設定されています.更新実行では,最大2個のノードが失敗し,最大2個のノードにリトライすることがあります. と呼ばれるスクリプトは,verifyupdatesinstalled.ps1更新実行が開始される前に,そのクラスタのすべてのノードが実行されている必要があります.もしすでに有効でない場合は,各クラスタノードにリモートシャットダウン Windows ファイアウォールルールグループが有効になります.コマンドはForceパラメータを使用しているため,cmdletは確認提示が表示されないまま実行されます.

-CauPluginArguments

各更新プラグインで使用する name=value pairs の集合を,議論として指定します.

例えば,一つのプラグインのドメイン引数を指定するには:

  • -@{Domain=Domain.local}

半球で分離した集合で複数のペアを指定できます.例えば:

  • -@{name1=value1;name2=value2;name3=value3}

これらの name=value pairs は,あなたが指定した CauPluginName パラメータに意味のあるものとする必要があります.複数のプラグインの為の議論を指定した場合,コマで分離した CauPluginName の値を渡す順に,name=value pairs の集合を指定してください.例えば:

  • -@{name1=value1;name2=value2;name3=value3},@{name4=value4;name5=value5}

デフォルトのMicrosoft.WindowsUpdatePlugin のプラグインでは,議論は必要ありません.以下の議論はオプションです:

'IncludeRecommendedUpdates'='\<Value\>':各ノードに重要な更新に加えて推奨された更新が適用されることを示唆するブール値.指定されていない場合,デフォルト値は偽である. - Windows Update Agentの標準的なクエリ文字列で,Windows Update Agentが各ノードに適用される更新をフィルタリングするために使用する基準を指定する.名前にはQueryStringを使用し,値としては,引用符で完全なクエリを付加する.指定されていない場合,デフォルトとして Microsoft.WindowsUpdatePluginのプラグインは以下の議論を使用します. - QueryString="IsInstalled=0 and Type='Software' and IsHidden=0 and IsAssigned=1"

デフォルトのクエリ・ストリングについて詳しくは,クエリ・ストリングに含まれるIsInstalledなどの基準については, [IUpdateSearcher::Search method] (/windows/win32/api/wuapi/nf-wuapi-iupdatesearcher-search) を参照してください.

Microsoft.HotfixPluginプラグインでは,次の議論が求められます.

  • HotfixRootFolderPath=\<Path\>: SMBのホットフィックスルーツフォルダへのUNC経路は,適用される更新が含まれる構造とホットフィックス構成ファイルを含む構造と共有しています.

次の議論は,Microsoft.HotfixPlugin**プラグインのオプションです.

RequireSmbEncryption=\<Value\>:ブルース値は,SMB シェアからのデータへのアクセスのためにSMB 暗号化が強制されることを示します.指定されていない場合は,デフォルト値は偽です.SMB シェアからアクセスされたデータの完全性を確保するために,プラグインは,シェアがSMB サインまたはSMB 暗号化に有効であることを要求します. - DisableAclChecks=\<Value\>:ブルース値は,プラグインがホットルーツフォルダーとホットフィックス構成ファイルで十分な許可を確認することを示すものです.指定されていない場合は,デフォルト値は偽です. - HotfixInstallerMinutes=<IntegerMinutes>**: ホットフィックスインストーラーがプロを許可する時間長さ.ocess to return. 指定されていない場合は,デフォルト値は30分です. - HotfixConfigFileName=\<name\>: ホットフィックス構成ファイルの名前.指定されていない場合は,デフォルト名は DefaultHotfixConfig.xmlMicrosoft.HotfixPlugin**プラグインの必要とオプションの議論については, [Cluster-Aware Updating plug-ins work] (/windows-server/failover-clustering/cluster-aware-updating-plug-ins) を参照してください.

## DESCRIPTION

The `Add-CauClusterRole` cmdlet adds the Cluster-Aware Updating (CAU) clustered role that provides
the self-updating functionality to the specified cluster. When the CAU clustered role has been added
to a cluster, the failover cluster can update itself on the schedule that is specified by the user,
without requiring an external computer to coordinate the cluster updating process.

To run this cmdlet, Windows PowerShell® remoting must be enabled on each node. To do this, run the
`Enable-PSRemoting` cmdlet. In addition, ensure that the **Windows Remote Management - Compatibility
Mode (HTTP-In)** firewall exception is enabled on each node.

## EXAMPLES

### Example 1: Add a CAU clustered role on the specified cluster at a specific interval

```powershell
$parameters = @{
    ClusterName = 'CONTOSO-FC1'
    DaysOfWeek = 'Tuesday',
                    'Saturday'
    WeeksOfMonth = '2',
                    '4'
    MaxFailedNodes = '2'
    MaxRetriesPerNode = '2'
    PostUpdateScript = '\\CONTOSOFileShare\scripts\verifyupdatesinstalled.ps1'
    RequireAllNodesOnline = $true
    EnableFirewallRules = $true
    Force = $true
}
Add-CauClusterRole @parameters
```

This command adds the CAU clustered role, using a default name, on the cluster called
**CONTOSO-FC1**. The CAU clustered role is configured to perform Updating Runs on Tuesdays and
Saturdays on the second and fourth weeks of each month. In an Updating Run, the maximum number of
failed nodes is two and the maximum number of retries per node is two. A script called
`verifyupdatesinstalled.ps1` runs on each node after it has been fully updated. Before an Updating
Run can begin, all the nodes of that cluster must be running. If it isn't already enabled, the
Remote Shutdown Windows Firewall rule group will be enabled on each cluster node. Because the
command uses the **Force** parameter, the cmdlet runs without displaying confirmation prompts.

This example uses splatting to pass parameter values from the `$parameters` variable to the command.
Learn more about [Splatting](/powershell/module/microsoft.powershell.core/about/about_splatting).

```powershell
$parameters = @{

    Force = $true

```

This command adds the CAU clustered role, using a default name, on the cluster called **CONTOSO-FC1**.
The CAU clustered role is configured to perform updates using the **Microsoft.WindowsUpdatePlugin**

**Microsoft.HotfixPlugin plug-in** using the hotfix root folder `\\CauHotfixSrv\shareName` and the

it isn't already enabled, the Remote Shutdown Windows Firewall rule group is enabled on each
cluster node. Because the command uses the **Force** parameter, the cmdlet runs without displaying
confirmation prompts.

This example uses splatting to pass parameter values from the `$parameters` variable to the command.
