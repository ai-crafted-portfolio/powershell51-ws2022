# about_PSReadLine_Functionsについて

## 短編説明

PSReadLineはPowerShellコンソールでコマンドライン編集の体験を向上させています.

## 長い説明

PSReadLine 2.0.0でPowerShell 5.1が発送される.現在のバージョンはPSReadLine 2.3.6です.現在のバージョンのPSReadLineはWindows PowerShell 5.1およびそれ以降にインストールされ,使用できます.一部の機能のために,PowerShell 7.2またはそれ以上のバージョンを実行する必要があります.

この記事ではPSReadLine 2.0.0が提供する機能を記録しています.これらの機能は,簡単にアクセスし,呼び出すためにキーストラックに結びつけることができます.

## Microsoft.PowerShell.PSConsoleReadLineクラスを使用する

以下は,Microsoft.PowerShell.PSConsoleReadLine** のクラスで提供されています.

## 編集の基本機能です.

### 堕胎は,

現在の行動を中止する,例えば:インクリメンタル・歴史検索.

- Emacsモード: `<Ctrl+g>`

### AcceptAndGetNext について

現在の入力を実行してみてください.実行可能な場合 (AcceptLineのような場合),次のリッドラインが呼び出されたときに,歴史から次の項目を呼び出す.

- Emacsモード: `<Ctrl+o>`

### AcceptLineは,

現在の入力を実行してみてください.現在の入力が不完全である場合 (例えば,閉括弧,括弧,引用が欠けている) では,次の行で継続プロンプトが表示されます. PSReadLine は,現在の入力を編集するキーを待っている.

Windowsモード:  - 窓モード`<Enter>`- Emacsモード: `<Enter>`- Vi insert mode: `<Enter>`

### AddLine を追加する

次の行に継続プロンプトが表示され,PSReadLineは現在の入力を編集するキーを待っている.これは,単行列が単独で完全な入力である場合でも,単行列入力を単行コマンドとして入力するのに役立ちます.

Windowsモード:  - 窓モード`<Shift+Enter>`- Emacsモード: `<Shift+Enter>`- Vi insert mode: `<Shift+Enter>`- Viコマンドモード: `<Shift+Enter>`

### バックワードDeleteChar

カーソルの前に文字を削除します.

Windowsモード:  - 窓モード`<Backspace>`     `<Ctrl+h>`- Emacsモード: `<Backspace>`     `<Ctrl+Backspace>`     `<Ctrl+h>`- Vi insert mode: `<Backspace>`- Viコマンドモード: `<X>`     `<d,h>`

### バックワードDeleteLine

BackwardKillLineのように - ラインの始まりからポイントまでのテキストを削除しますが,削除されたテキストをキルリングに入れません.

Windowsモード:  - 窓モード`<Ctrl+Home>`- Vi insert mode: `<Ctrl+u>`     `<Ctrl+Home>`- Viコマンドモード: `<Ctrl+u>`     `<Ctrl+Home>`     `<d,0>`

### バックワードDeleteWord

前回の単語を削除します.

- Viコマンドモード: `<Ctrl+w>`     `<d,b>`

### バックワードKillLine

入力開始からクリアされたテキストがキルリングに配置されます.

- Emacsモード: `<Ctrl+u>`     `<Ctrl+x,Backspace>`

### バックワードKillWord

カーソルへの入力を,現在の単語開始からクリアする.カーソルは単語の間にある場合,カーソルへの入力は,前の単語開始からクリアされます.クリアされたテキストは,キルリングに配置されます.

Windowsモード:  - 窓モード`<Ctrl+Backspace>`- Emacsモード: `<Alt+Backspace>`     `<Escape,Backspace>`- Vi insert mode: `<Ctrl+Backspace>`- Viコマンドモード: `<Ctrl+Backspace>`

### CancelLine キャンセル

現在の入力をキャンセルし,画面上に入力を残しますが,ホストに戻りますのでプロンプトが再び評価されます.

- Vi insert mode: `<Ctrl+c>`- Viコマンドモード: `<Ctrl+c>`

### コピー

選択された地域をシステムクリップボードにコピーします. 選択された地域がない場合は,全行をコピーします.

Windowsモード:  - 窓モード`<Ctrl+C>`

### CopyOrCancelLine をコピーする

テキストが選択された場合,クリップボードにコピーしてください.そうでなければ,行をキャンセルします.

Windowsモード:  - 窓モード`<Ctrl+c>`- Emacsモード: `<Ctrl+c>`

### 切断する

削除されたテキストをシステムクリップボードに配置する選択された地域を削除します.

Windowsモード:  - 窓モード`<Ctrl+x>`

### 削除チャートは

カーソルの下にある文字を削除します.

Windowsモード:  - 窓モード`<Delete>`- Emacsモード: `<Delete>`- Vi insert mode: `<Delete>`- Viコマンドモード: `<Delete>`     `<x>`     `<d,l>`     `<d,Space>`

### DeleteCharteOrExit を削除する

カーソルの下の文字を削除するか,行が空いている場合は,プロセスを終了します.

- Emacsモード: `<Ctrl+d>`

### 削除EndOfWord

単語の終わりまで削除します.

- Viコマンドモード: `<d,e>`

- Viコマンドモード: `<d,w>`

### InsertLineAbove を入力してください.

### InsertLineBelow を入力してください.

カーソルが現在のラインにどこに位置するかにかかわらず,現在のラインの下には新しい空きラインが作成されます.カーソルは新しい行の開始に移動します.

Windowsモード:  - 窓モード`<Shift+Ctrl+Enter>`

### InvertCase は

現在の文字のケースを逆にして次の文字に移す.

- Viコマンドモード: `<~>`

### キルライン

入力をクリアする際に,カーソルから入力の終わりまで入力をクリアする.クリアされたテキストは,キルリングに配置されます.

- Emacsモード: `<Ctrl+k>`

### キルレジオン

カーソルとマークの間のテキストを消します.

- 機能は無制限です.

### キルワード

カーソルから現在の単語の終わりまで入力をクリアする.カーソルは単語の間にある場合,カーソルから次の単語の終わりまで入力がクリアされます.クリアされたテキストはキルリングに配置されます.

Windowsモード:  - 窓モード`<Ctrl+Delete>`- Emacsモード: `<Alt+d>`     `<Escape,d>`- Vi insert mode: `<Ctrl+Delete>`- Viコマンドモード: `<Ctrl+Delete>`

### パスタ

システムクリップボードからテキストをペーストします.

Windowsモード:  - `<Ctrl+v>`     `<Shift+Insert>`- Vi insert mode: `<Ctrl+v>`- Viコマンドモード: `<Ctrl+v>`

[!IMPORTANT] > **Paste**機能を使用する際,クリップボードのすべてのコンテンツはPSReadLineの入力バッファに貼り付けられます.入力バッファは > PowerShell パースに転送されます.コンソール >アプリケーションの **右クリック** パースト方法を使用してペーストされた入力が入力バッファで1>文字に一度にコピーされます.入力バッファは, newline >文字がコピーされたときにパーサーに転送されます.したがって,入力は一度に1行にパーストされます.ペースト方法の違いによって実行行動が異なります.

### パステアフター

クリップボードをカーソルの後に貼って,カーソルをペーストされたテキストの端に移動します.

- Viコマンドモード: `<p>`

### パスタBefore

クリップボードをカーソルの前に貼って,カーソルをペーストされたテキストの最後に移動します.

- Viコマンドモード: `<P>`

### PrependAndAccept 準備と受け入れ

"#"を入力して,行を承認します.

- Viコマンドモード: `<#>`

### 準備ができている

撤廃を撤回する.

Windowsモード:  - `<Ctrl+y>`- Vi insert mode: `<Ctrl+y>`- Viコマンドモード: `<Ctrl+y>`

### RepeatLastCommand を繰り返す

最後のテキスト変更を繰り返します.

- Viコマンドモード: `<.>`

### リバー・ライン

すべての入力を現在の入力に変換します.

Windowsモード:  - `<Escape>`- Emacsモード: `<Alt+r>`     `<Escape,r>`

### EndOfLineです.

# about_PSReadLine_Functions

## Short description

PSReadLine provides an improved command-line editing experience in the
PowerShell console.

## Long description

PowerShell 5.1 ships with PSReadLine 2.0.0. The current version is PSReadLine
2.3.6. The current version of PSReadLine can be installed and used on Windows
PowerShell 5.1 and newer. For some features, you need to be running PowerShell
7.2 or higher.

This article documents the functions provided by PSReadLine 2.0.0. These
functions can be bound to keystrokes for easy access and invocation.

## Using the Microsoft.PowerShell.PSConsoleReadLine class

The following functions are available in the class
**Microsoft.PowerShell.PSConsoleReadLine**.

## Basic editing functions

### Abort

Abort current action, for example: incremental history search.

- Emacs mode: `<Ctrl+g>`

### AcceptAndGetNext

Attempt to execute the current input. If it can be executed (like AcceptLine),
then recall the next item from history the next time ReadLine is called.

- Emacs mode: `<Ctrl+o>`

### AcceptLine

Attempt to execute the current input. If the current input is incomplete (for
example there's a missing closing parenthesis, bracket, or quote) then the
continuation prompt is displayed on the next line and PSReadLine waits for
keys to edit the current input.

- Windows mode: `<Enter>`
- Emacs mode: `<Enter>`
- Vi insert mode: `<Enter>`

### AddLine

The continuation prompt is displayed on the next line and PSReadLine waits for
keys to edit the current input. This is useful to enter multi-line input as a
single command even when a single line is complete input by itself.

- Windows mode: `<Shift+Enter>`
- Emacs mode: `<Shift+Enter>`
- Vi insert mode: `<Shift+Enter>`
- Vi command mode: `<Shift+Enter>`

### BackwardDeleteChar

Delete the character before the cursor.

- Windows mode: `<Backspace>`, `<Ctrl+h>`
- Emacs mode: `<Backspace>`, `<Ctrl+Backspace>`, `<Ctrl+h>`
- Vi insert mode: `<Backspace>`
- Vi command mode: `<X>`, `<d,h>`

### BackwardDeleteLine

Like BackwardKillLine - deletes text from the point to the start of the line,
but doesn't put the deleted text in the kill-ring.

## Custom key binding support APIs

The following functions are public in Microsoft.PowerShell.PSConsoleReadLine,
but can't be directly bound to a key. Most are useful in custom key bindings.

```csharp
void AddToHistory(string command)
```

Add a command line to history without executing it.

```csharp
void ClearKillRing()
```

Clear the kill-ring. This is mostly used for testing.

```csharp
void Delete(int start, int length)
```

Delete length characters from start. This operation supports undo/redo.

```csharp
void Ding()
```

Perform the Ding action based on the user's preference.

```csharp
void GetBufferState([ref] string input, [ref] int cursor)
void GetBufferState([ref] Ast ast, [ref] Token[] tokens,
  [ref] ParseError[] parseErrors, [ref] int cursor)
```

These two functions retrieve useful information about the current state of the
input buffer. The first is more commonly used for simple cases. The second is
used if your binding is doing something more advanced with the Ast.

```csharp
IEnumerable[Microsoft.PowerShell.KeyHandler]
  GetKeyHandlers(bool includeBound, bool includeUnbound)

```

This function is used by `Get-PSReadLineKeyHandler` and probably isn't useful
in a custom key binding.

```csharp
Microsoft.PowerShell.PSConsoleReadLineOptions GetOptions()
```

This function is used by Get-PSReadLineOption and probably isn't too useful in
a custom key binding.

```csharp
void GetSelectionState([ref] int start, [ref] int length)
```

If there's no selection on the command line, the function returns -1 in both
start and length. If there's a selection on the command line, the start and

void Insert(char c)
void Insert(string s)

## Notes

Behavior of the OnIdle event

- When PSReadLine is in use, the **OnIdle** event is fired when `ReadKey()`
  times out (no typing in 300ms). The event could be signaled while the user is
  in the middle of editing a command line, for example, the user is reading
  help to decide which parameter to use.

  Beginning in PSReadLine 2.2.0-beta4, **OnIdle** behavior changed to signal
  the event only if there's a `ReadKey()` timeout and the current editing
  buffer is empty.
