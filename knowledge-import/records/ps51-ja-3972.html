# セット-WSManInstance を設定する

## SYNOPSIS は,リソースに関連した管理情報を修正します.

## SYNTAXは,のシンタックスです.

### コンピュータ名 (デフォルト) 

```
Set-WSManInstance [-ApplicationName <String>] [-ComputerName <String>] [-Dialect <Uri>]
 [-FilePath <String>] [-Fragment <String>] [-OptionSet <Hashtable>] [-Port <Int32>]
 [-ResourceURI] <Uri> [[-SelectorSet] <Hashtable>] [-SessionOption <SessionOption>]
 [-UseSSL] [-ValueSet <Hashtable>] [-Credential <PSCredential>]
 [-Authentication <AuthenticationMechanism>] [-CertificateThumbprint <String>]
 [<CommonParameters>]
```

### URI 

```
Set-WSManInstance [-ConnectionURI <Uri>] [-Dialect <Uri>] [-FilePath <String>]
 [-Fragment <String>] [-OptionSet <Hashtable>] [-ResourceURI] <Uri>
 [[-SelectorSet] <Hashtable>] [-SessionOption <SessionOption>] [-ValueSet <Hashtable>]
 [-Credential <PSCredential>] [-Authentication <AuthenticationMechanism>]
 [-CertificateThumbprint <String>] [<CommonParameters>]
```

## 記述は,

   `Set-WSManInstance`cmdlet は,リソースに関連した管理情報を修正します.

このcmdletは WinRM接続/輸送層を使用して情報を変更します.

## 例えは

### 例1: ローカルコンピュータのオーディナーを無効にします.

```powershell
$params = @{
    ResourceURI = 'winrm/config/listener'
    SelectorSet = @{address = '*'; transport = 'https'}
    ValueSet    = @{Enabled = 'false'}
}
Set-WSManInstance @params
```

```Output
cfg                   : http://schemas.microsoft.com/wbem/wsman/1/config/listener
xsi                   : http://www.w3.org/2001/XMLSchema-instance
lang                  : en-US
Address               : *
Transport             : HTTPS
Port                  : 443
Hostname              :
Enabled               : false
URLPrefix             : wsman
CertificateThumbprint :
ListeningOn           : {127.0.0.1, 172.30.168.171, ::1, 2001:4898:0:fff:0:5efe:172.30.168.171...}
```

このコマンドは,ローカルコンピュータのHTTPSリスナーを無効にする.

>!IMPORTANT] > 指定されたプロパティと一致する際には,ValueSetのパラメータはケースセンシティブです.

例えば,このコマンドでは

これは失敗する: `-ValueSet @{enabled="False"}`

これは成功する: `-ValueSet @{Enabled="False"}`

### 例2: 局部コンピュータで最大封筒サイズを設定する

```powershell
Set-WSManInstance -ResourceURI winrm/config -ValueSet @{MaxEnvelopeSizekb = "200"}
```


このコマンドは,ローカルコンピュータの **MaxEnvelopeSizekb**値を200に設定します.

>!IMPORTANT] > 指定されたプロパティと一致する際には,ValueSetのパラメータはケースセンシティブです.

例えば,上記のコマンドを使用します.

これは失敗する: `-ValueSet @{MaxEnvelopeSizeKB ="200"}`

これは成功する: `-ValueSet @{MaxEnvelopeSizekb ="200"}`

### 例4:入力ファイルを使ってリソースを管理する

次のコマンドでは管理リソースを更新するために **FilePath**パラメータを使用します. **ResourceURI**と **SelectorSet**パラメータを使用して管理リソースを指定します.

```powershell
$params = @{
    Action         = 'StopService'
    ResourceUri    = 'wmicimv2/Win32_Service'
    SelectorSet    = @{Name = 'spooler'}
    FilePath       = 'C:\input.xml'
    Authentication = 'Default'
}
Invoke-WSManAction @params
```

このコマンドは,ファイルからの入力を使用して,スプーラーサービス上の **StopService** 方法を呼びます.`input.xml`ファイルには以下の内容が含まれています:

```xml
<p:StopService_INPUT xmlns:p="http://schemas.microsoft.com/wbem/wsman/1/wmi/root/cimv2/Win32_Service" />
```

## パラメータは

### -ApplicationName

接続中のアプリケーション名を指定します. **ApplicationName**パラメータのデフォルト値は"WSMAN"です. リモートエンドポイントの完全な識別子は以下の形式です:

`<transport>://<server>:<port>/<ApplicationName>`

例えば:

`http://server01:8080/WSMAN`

セッションをホストするインターネット情報サービス (IIS) は,このエンドポイントで要求を指定されたアプリケーションに転送します.このデフォルト設定は です.`WSMAN`このパラメータは,Windows PowerShellを実行しているコンピュータに複数のコンピュータがリモート接続を確立するときに使用するように設計されています.この場合は,効率のためにWeb Services for Management (WS-Management) をホストします.

### -認証

サーバーで使用する認証メカニズムを指定します.可能な値は以下の通りです.

 - -`Basic`:BASICは,ユーザ名とパスワードが,サーバーまたはプロクシーに明晰文で送信されるスキームです. - `Default`: WS-Management プロトコルで実装された認証方法を使用します.これはデフォルトです. - `Digest`: ダイジェストは,課題に対してサーバーに指定されたデータ文字列を使用するチャレンジ応答のスキームです. - `Kerberos`: クライアントコンピュータとサーバーはカーベロス証明書を使用して相互認証します. - `Negotiate`:交渉は,サーバーまたは代理で認証のために使用するスキームを決定するために交渉する挑戦応答スキームです.例えば,このパラメータ値は,交渉によってKerberosプロトコルまたはNTLMが使用されているかどうかを判断することができます. - `CredSSP`: クレデントセキュリティサポートプロバイダー (CredSSP) 認証を使用し,ユーザーに認証を委譲することができます.このオプションは,リモートコンピュータで実行されるコマンドに設計されていますが,他のリモートコンピュータでデータ収集または追加コマンドを実行します.

> [!CAUTION] > CredSSPは,ローカルコンピュータからリモートコンピュータにユーザーの認証情報を委託する.この慣行により,リモート操作のセキュリティリスクが増加する.リモートコンピュータが > 侵害されている場合,認証が渡されたとき,認証はネットワーク > セッションを制御するために使用できます.

# Set-WSManInstance

## SYNOPSIS
Modifies the management information that is related to a resource.

## SYNTAX

### ComputerName (Default)

```
Set-WSManInstance [-ApplicationName <String>] [-ComputerName <String>] [-Dialect <Uri>]
 [-FilePath <String>] [-Fragment <String>] [-OptionSet <Hashtable>] [-Port <Int32>]
 [-ResourceURI] <Uri> [[-SelectorSet] <Hashtable>] [-SessionOption <SessionOption>]
 [-UseSSL] [-ValueSet <Hashtable>] [-Credential <PSCredential>]
 [-Authentication <AuthenticationMechanism>] [-CertificateThumbprint <String>]
 [<CommonParameters>]
```

### URI

```
Set-WSManInstance [-ConnectionURI <Uri>] [-Dialect <Uri>] [-FilePath <String>]
 [-Fragment <String>] [-OptionSet <Hashtable>] [-ResourceURI] <Uri>
 [[-SelectorSet] <Hashtable>] [-SessionOption <SessionOption>] [-ValueSet <Hashtable>]
 [-Credential <PSCredential>] [-Authentication <AuthenticationMechanism>]
 [-CertificateThumbprint <String>] [<CommonParameters>]
```

## DESCRIPTION

The `Set-WSManInstance` cmdlet modifies the management information that is related to a resource.

This cmdlet uses the WinRM connection/transport layer to modify the information.

## EXAMPLES

### Example 1: Disable a listener on the local computer

```powershell
$params = @{
    ResourceURI = 'winrm/config/listener'
    SelectorSet = @{address = '*'; transport = 'https'}
    ValueSet    = @{Enabled = 'false'}
}
Set-WSManInstance @params
```

```Output
cfg                   : http://schemas.microsoft.com/wbem/wsman/1/config/listener
xsi                   : http://www.w3.org/2001/XMLSchema-instance
lang                  : en-US
Address               : *
Transport             : HTTPS
Port                  : 443
Hostname              :
Enabled               : false
URLPrefix             : wsman
CertificateThumbprint :
ListeningOn           : {127.0.0.1, 172.30.168.171, ::1, 2001:4898:0:fff:0:5efe:172.30.168.171...}
```

This command disables the HTTPS listener on the local computer.

> [!IMPORTANT]
> The **ValueSet** parameter is case-sensitive when matching the properties specified.

For example, in this command,

This fails: `-ValueSet @{enabled="False"}`

This succeeds: `-ValueSet @{Enabled="False"}`

### Example 2: Set the maximum envelope size on the local computer

```powershell
Set-WSManInstance -ResourceURI winrm/config -ValueSet @{MaxEnvelopeSizekb = "200"}
```


This command sets the **MaxEnvelopeSizekb** value to 200 on the local computer.

For example, using the above command.

This fails: `-ValueSet @{MaxEnvelopeSizeKB ="200"}`

This succeeds: `-ValueSet @{MaxEnvelopeSizekb ="200"}`

### Example 4: Manage a resource using an input file

The following command uses the **FilePath** parameter to update a management resource. Specify the
management resource using the **ResourceURI** and **SelectorSet** parameters.

```powershell
$params = @{
    Action         = 'StopService'
    ResourceUri    = 'wmicimv2/Win32_Service'
    SelectorSet    = @{Name = 'spooler'}
    FilePath       = 'C:\input.xml'
    Authentication = 'Default'
}
Invoke-WSManAction @params
```

This command calls the **StopService** method on the Spooler service using input from a file. The
`input.xml` file contains the following content:

```xml
<p:StopService_INPUT xmlns:p="http://schemas.microsoft.com/wbem/wsman/1/wmi/root/cimv2/Win32_Service" />
```

## PARAMETERS

### -ApplicationName

Specifies the application name in the connection. The default value of the **ApplicationName**
parameter is "WSMAN". The complete identifier for the remote endpoint is in the following format:

`<transport>://<server>:<port>/<ApplicationName>`

For example:

`http://server01:8080/WSMAN`

Internet Information Services (IIS), which hosts the session, forwards requests with this endpoint
to the specified application. This default setting of `WSMAN` is appropriate for most uses. This
parameter is designed to be used when numerous computers establish remote connections to one
computer that is running Windows PowerShell. In this case, IIS hosts Web Services for Management
(WS-Management) for efficiency.

### -Authentication

Specifies the authentication mechanism to be used at the server.
Possible values are:

- `Basic`: Basic is a scheme in which the user name and password are sent in clear text to the
  server or proxy.
- `Default` : Use the authentication method implemented by the WS-Management protocol. This is the
  default.
- `Digest`: Digest is a challenge-response scheme that uses a server-specified data string for the
  challenge.
- `Kerberos`: The client computer and the server mutually authenticate by using Kerberos
  certificates.
- `Negotiate`: Negotiate is a challenge-response scheme that negotiates with the server or proxy to
  determine the scheme to use for authentication. For example, this parameter value allows
  negotiation to determine whether the Kerberos protocol or NTLM is used.
- `CredSSP`: Use Credential Security Support Provider (CredSSP) authentication, which allows the
  user to delegate credentials. This option is designed for commands that run on one remote computer
  but collect data from or run additional commands on other remote computers.

> [!CAUTION]
> CredSSP delegates the user's credentials from the local computer to a remote computer. This
> practice increases the security risk of the remote operation. If the remote computer is
> compromised, when credentials are passed to it, the credentials can be used to control the network
> session.

```yaml
Accepted values: None, Default, Digest, Negotiate, Basic, Kerberos, ClientCertificate, Credssp

```
