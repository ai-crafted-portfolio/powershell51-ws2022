# Remove-ADComputerServiceAccount を削除する

## SYNOPSISは,コンピュータから1つ以上のサービスアカウントを削除します.

## SYNTAXは,のシンタックスです.

```
Remove-ADComputerServiceAccount [-WhatIf] [-Confirm] [-AuthType <ADAuthType>] [-Credential <PSCredential>]
 [-Identity] <ADComputer> [-Partition <String>] [-PassThru] [-Server <String>]
 [-ServiceAccount] <ADServiceAccount[]> [<CommonParameters>]
```

## 記述 **Remove-ADComputerServiceAccount** cmdlet は,アクティブディレクトリコンピュータからサービスアカウントを削除します.

*Identity* パラメータは,削除するサービスアカウントを含むアクティブディレクトリコンピュータを指定します.コンピュータをその名,GUID,セキュリティ識別子 (SID) またはセキュリティアカウント管理者 (SAM) アカウント名によって識別できます.また, *Identity* パラメタをコンピュータオブジェクト変数に設定できます.例えば, `$<localComputerobject>`例えば,コンピュータオブジェクトを回収するために **Get-ADComputer** cmdlet を使用し,パイプラインを介してオブジェクトを **Remove-ADComputerServiceAccount** cmdlet に転送できます.

*サービスアカウント* パラメータは,削除するサービスアカウントを指定します.サービスアカウントをその名,GUI,セキュリティ識別子 (SID) またはセキュリティアカウント管理者 (SAM) 口座名によって識別できます.また,サービスアカウントオブジェクト変数を指定できます.例えば,`$<localServiceAccountObject>`.複数のサービスアカウントを指定している場合は,逗号別列を使用してください.

## 例えは

### 例1:サービスアカウントを削除する```
PS C:\> Remove-ADComputerServiceAccount -Identity ComputerAcct1 -ServiceAccount SvcAcct1
```

このコマンドは,SVCACT1のサービスアカウントをコンピュータアカウントから削除します.

### 例2:複数のサービスアカウントを削除する```
PS C:\> Remove-ADComputerServiceAccount -Identity ComputerAcct1 -ServiceAccount SvcAcct1,SvcAcct2
```

このコマンドは,SvcAcct1およびSvcAcct2のサービスアカウントをコンピュータアカウントから削除します.

# Remove-ADComputerServiceAccount

## SYNOPSIS
Removes one or more service accounts from a computer.

## SYNTAX

```
Remove-ADComputerServiceAccount [-WhatIf] [-Confirm] [-AuthType <ADAuthType>] [-Credential <PSCredential>]
 [-Identity] <ADComputer> [-Partition <String>] [-PassThru] [-Server <String>]
 [-ServiceAccount] <ADServiceAccount[]> [<CommonParameters>]
```

## DESCRIPTION
The **Remove-ADComputerServiceAccount** cmdlet removes service accounts from an Active Directory computer.

The *Identity* parameter specifies the Active Directory computer that contains the service accounts to remove.
You can identify a computer by its distinguished name, GUID, security identifier (SID) or Security Accounts Manager (SAM) account name.
You can also set the *Identity* parameter to a computer object variable, such as `$<localComputerobject>`, or pass a computer object through the pipeline to the *Identity* parameter.
For example, you can use the **Get-ADComputer** cmdlet to retrieve a computer object and then pass the object through the pipeline to the **Remove-ADComputerServiceAccount** cmdlet.

The *ServiceAccount* parameter specifies the service accounts to remove.
You can identify a service account by its distinguished name, GUID, security identifier (SID) or security accounts manager (SAM) account name.
You can also specify service account object variables, such as `$<localServiceAccountObject>`.
If you are specifying more than one service account, use a comma-separated list.

## EXAMPLES

### Example 1: Remove a service account
```
PS C:\> Remove-ADComputerServiceAccount -Identity ComputerAcct1 -ServiceAccount SvcAcct1
```

This command removes a service account SvcAcct1 from a Computer Account ComputerAcct1.

### Example 2: Remove multiple service accounts
```
PS C:\> Remove-ADComputerServiceAccount -Identity ComputerAcct1 -ServiceAccount SvcAcct1,SvcAcct2
```

This command removes service accounts SvcAcct1 and SvcAcct2 from a Computer Account ComputerAcct1.

### -Partition
Specifies the distinguished name of an Active Directory partition.
The distinguished name must be one of the naming contexts on the current directory server.
The cmdlet searches this partition to find the object defined by the *Identity* parameter.

In many cases, a default value is used for the *Partition* parameter if no value is specified. 
The rules for determining the default value are given below. 
Note that rules listed first are evaluated first and once a default value can be determined, no further rules are evaluated.

In Active Directory Domain Services environments, a default value for *Partition* is set in the following cases: 

- If the *Identity* parameter is set to a distinguished name, the default value of *Partition* is automatically generated from this distinguished name.
- If running cmdlets from an Active Directory provider drive, the default value of *Partition* is automatically generated from the current path in the drive. 
- If none of the previous cases apply, the default value of *Partition* is set to the default partition or naming context of the target domain.

In Active Directory Lightweight Directory Services (AD LDS) environments, a default value for *Partition* is set in the following cases:

- If the *Identity* parameter is set to a distinguished name, the default value of *Partition* is automatically generated from this distinguished name. 
- If running cmdlets from an Active Directory provider drive, the default value of *Partition* is automatically generated from the current path in the drive. 
- If the target AD LDS instance has a default naming context, the default value of *Partition* is set to the default naming context. 
To specify a default naming context for an AD LDS environment, set the **msDS-defaultNamingContext** property of the Active Directory directory service agent object (**nTDSDSA**) for the AD LDS instance. 
- If none of the previous cases apply, the *Partition* parameter will not take any default value.
